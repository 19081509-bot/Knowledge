# 写库规范与分类体系（Obsidian 新结构）

> 2026-08-27 东哥定。覆盖旧规"只记解决问题案例"——自今起 Obsidian 为 agent 共享主库，AI 产出按类持续归档。
> 适用：Windows Hermes（总调度）及调度下所有 Mac agent。查证优先级见 `60-AI规则/agent协作总则-查证优先级.md`。

## 一、顶层结构

```
知识库/
├── 00-inbox/          未归类暂存（你随手丢 / agent 暂存，待清洗）
├── 10-钻井工程/       钻井 / 定向井 / 水平井 / 短半径 / 双分支井 / 井眼轨迹
├── 20-书籍/           书籍蒸馏 / 人物传记 / 读书笔记
├── 30-金融/           投资 / ETF / 股票 / 基金 / 复利 / 风控 / 经济概念
├── 40-财务/           个人收支 / 资产快照 / 账单 / 税务
├── 50-AI项目/         AI 项目 / 计划书 / 模型模拟 / 商业想法
├── 60-AI规则/         agent 协作规则 / 分工架构 / 查证优先级（给 agent 看的）
├── 70-个人规划/       学习成长方案 / 健康 / 年度目标 / 成长复盘
├── 微信聊天记录/      按联系人：01-原始导出/<人>/  +  02-清洗后/<人>.md
├── _ai/               agent 元数据 / workflows / 技能
└── AI对话存档/        调试日志类
```

## 二、分类双轴

- **微信聊天文字** → 主维度=**联系人**（落 `微信聊天记录/02-清洗后/<人>.md`）；同时按内容打标签（如 `#钻井` `#金融`）便于在 10~70 中经 Dataview 浮现。
- **文档 / PPT / PDF / Word / Excel / 网页抓取文本** → 主维度=**内容**，归入 10~70 某一类（见第三节判类逻辑）。

## 四、各采集通道落库路径

| 通道 | 落库位置 |
|---|---|
| Windows 直接丢给 Hermes（粘贴/文件） | 按内容判 10~70；纯碎片进 00-inbox |
| 微信聊天记录（WeChatDataAnalysis 导出） | `微信聊天记录/01-原始导出/<人>/` → 清洗后 `02-清洗后/<人>.md` |
| 豆包等网页抓取文本 | 按内容判 10~70 |
| 文档/PPT/PDF/Word/Excel | 按内容判 10~70（PDF 有文字层直接提；扫描件走 OCR/视觉） |

## 五、文件命名与标签

- 文件名：`YYYYMMDD-主题.md`（沿用既有习惯）
- 头部必带：`tags:`（含主类标签 + 交叉标签）、`source:`（来源=哪个 agent / 哪个通道 / 哪个联系人）
- 例：`70-个人规划/20260827-学习成长方案.md` 头：`tags: [[个人规划]] [[健康]]` `source: Windows Hermes`

## 六、00-inbox 清洗规则

- 仅放"未归类/原始碎片"；agent 产出已归类内容**不进 inbox**。
- 清洗触发：你跟我说"清 inbox" / 或 cron 周期扫。
- 清洗动作：读 00-inbox → 判类 → 移入 10~70（或微信聊天记录）→ 加标签；清空前回报移了哪些。

## 七、agent 写库流程（铁律）

记忆 → Obsidian → 推理 → 网络论证 → 实施（详见查证优先级总则）。
写库前必先判类，禁止无归类堆 inbox。
