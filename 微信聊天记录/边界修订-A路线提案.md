## 一、背景

1. Hermes 简报阶段1 已完成（目录、`Mac安装指引.md` 均就绪）。
2. 东哥指示：Windows 侧 WeChatDataAnalysis 交由 Hermes 处理；Mac 侧另找替代方案。
3. Mac 侧排查结论：本机为 Intel Mac，WeChatDataAnalysis 官方仅发 arm64 构建，**无法在本机运行**；PyWxDump 亦不支持 Intel Mac。
4. 调研发现 `tzwkb/wechat-decrypt`（Agent Skill + Python + MCP，支持微信 4.x、Intel 可用）可作 Mac 侧深接管方案（A 路线）。

## 二、现状边界（00-说明.md 原文）

> 只处理微信客户端自带的明文导出（txt/html）；**绝不读微信加密库**（SQLCipher AES-256，逆向/破解一律不做）。

## 三、提议的新边界（仅用于 A 路线）

| 项 | 提议 |
|----|------|
| 解密范围 | 仅**本机**微信 4.x 本地库，只读解密，绝不外传 |
| 外传 | 解出的明文、key 均不得离开本机（清洗产物照旧进知识库脱敏后同步） |
| 部署形态 | **先验证制**：先提 key + 解单库验证 4.1.11 兼容，通过后再谈是否常驻 MCP |
| 微信数据 | 不改动任何微信原始文件/原始库 |
| 阶段2 清洗 | 流程不变：`01-原始导出/` → `02-清洗后/`（A 路线导出产物可等同处理） |

## 四、已知风险（采纳即接受，不隐瞒）

1. macOS 取 key 需 `sudo codesign --force --deep --sign -` 重签名微信 → **覆盖腾讯签名（破坏性）**，提完需恢复/重装微信（聊天记录在独立容器目录，重装不丢）；提 key 时需东哥扫码登录一次。
2. 微信升级后需重新提 key（SKILL.md 已说明）。
3. Intel Mac 自动语音转写默认后端（mlx-whisper）为 Apple Silicon 专用，**Intel 需另配后端**（语音转写非必需项，可跳过）。
4. 仓库成熟度低（stars=4，个人项目），后续兼容性靠自己跟进。
