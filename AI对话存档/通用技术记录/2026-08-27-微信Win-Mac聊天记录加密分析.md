# 微信 Win/Mac 聊天记录加密分析（2026-08-27 实测）

> 背景：原计划让 Mac 下 codex-cli 处理微信聊天记录文本（剔除图片/视频/表情包），但它卡在"寻找加密方式"。本篇是实测后的结论与正路方案。

## 一、核心结论

**微信 4.0 新版（Windows 与 Mac 同代）聊天库 = SQLCipher(AES-256) 加密，不是明文。**
"Windows 没加密"是**错觉**——旧版 Windows 3.x 靠从运行中进程内存 dump 密钥才显得容易，新版结构已大改，与 Mac 同样难，都不该逆向。

## 二、实证（两设备均实测）

### Mac（4.1.11）
- 库路径：`~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/wxid_a2yqqlntmrs122_7e36/db_storage/message/message_1.db`
- 文件头：`c1 59 7f 25 2e 14 ef eb …`（随机密文，非 `SQLite` 魔数）→ 确认 SQLCipher
- 密钥**不在 macOS Keychain**（`security dump-keychain` 无 wechat 条目），存在 `db_storage/MMKV/*.mmkv`（腾讯自研，非 plist）

### Windows（本机，D 盘，4.0 新版）
- 库路径：`D:\xwechat_files\wd663646_9faa\db_storage\message\message_1.db`（6.7 MB）
- 文件头 hex：`b4 af 4e dd c4 ba cf 0e a4 47 72 39 a9 d4 99 3c`（随机密文，非 `SQLite` 魔数）→ 确认 SQLCipher
- D 盘结构：`D:\xwechat_files\`（含 `wd663646_9faa` 与 `wxid_a2yqqlntmrs122_7e36` 两账号、`Backup`、`all_users`）；`D:\xwechat_files\WeChat Files\`、`D:\微信文件\WeChat Files\` 仅为媒体/文件缓存，非聊天库
- 旧版路径 `C:\Users\Administrator\Documents\WeChat Files` 仍存在（仅 All Users / 测试文件），无实际库

## 三、版本差异（为何有"Windows 不加密"错觉）

| 版本 | 加密？ | 提取难度 |
|---|---|---|
| 微信 Windows **3.x 及更早** | 也是 SQLCipher | 密钥可从运行中进程内存 dump，开源 `PyWxDump` 成熟 → 用起来"跟明文一样" |
| 微信 **4.0 新版（本机）** | 加密 + 结构大改（radium / xwechat_files / MMKV） | 密钥挪进 MMKV，PyWxDump 对 4.0 支持差，变难 |
| 微信 Mac 4.x | 同上 | MMKV + 私有 KDF 派生，开源工具适配差 |

## 四、正路方案（两设备一致，已落地）

**不逆向、不碰加密库**，走微信自带导出：

1. 微信客户端 → 聊天窗口 `...` → 导出聊天记录 → 存 txt/html（媒体只留占位符 `[图片][视频][表情]`）
2. 清洗脚本剔除媒体占位行，留纯文字 + 时间，交 AI 归档

### 清洗脚本（已写 + 自测通过）
- Mac：`~/wechat_chat/clean_chat.py`（标准库，不联网不解密）
- 用法：`cd ~/wechat_chat && python3 clean_chat.py <导出文件或目录> --out cleaned`
- 剔除：`[图片][照片][视频][表情][动画表情][语音][视频通话][文件][链接][位置][名片][红包][转账][小程序][合并转发][撤回][拍一拍]` 及 `<img>/<video>`
- 输出：按会话 Markdown 到 `cleaned/`
- Windows 端同理（脚本未建，需补一份 + 工作目录）

## 五、AI 工具排查结论（顺带记录）

- **codex-cli（Mac）**：处理微信任务时卡在"找加密方式"——实为 idle（CPU 0%、子进程仅交互壳），非死循环；末端 `deepseek-ai/DeepSeek-V4-Flash default · ~` 是空闲提示符。根因：缺源文件 + 不会"卡住就上报"。已纠正为"只处理明文导出"，并改用直写脚本接管。
- **Claude Code（Mac）**：CLI 在 `nvm node v24` 下 `/Users/w/.nvm/versions/node/v24.15.0/bin/claude`（v2.1.246）可用；`/usr/local/bin/claude` 是死链（npm 模块已卸），勿用。配置 `~/.claude/settings.json`：`ANTHROPIC_BASE_URL=http://127.0.0.1:17645/anthropic`，模型 `deepseek-ai/DeepSeek-V4-Flash`（relay-ai 中转，**无需官方账号**）。实测 `claude -p "只回两个字: 收到"` → 输出 `收到` ✅。注意：`Claude.app` 桌面版 SSH 下读钥匙串失败（`errSecInteractionNotAllowed`），**不能当无头 CLI 用**。
- **错误排查教训**：验 Claude Code 可用性应查 `~/.claude/settings.json` 的 `ANTHROPIC_BASE_URL` + 用正确模型名，不要误测桌面版、不要乱填 `claude-sonnet-4`（已 retire）。
