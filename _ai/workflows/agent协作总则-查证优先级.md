# Agent 协作总则 · 查证优先级与回答流程

> 2026-08-27 东哥定。适用于 Windows Hermes(总调度)及调度下的所有 Mac agent(Claude Code / Codex / OpenClaw / hermes-mac)。
> 本则写入 Obsidian,作为 agent 可读的协作铁律;东哥提问时各 agent 依此链路调取。

## 一、回答/查证的优先级链路(严格顺序)

当东哥提出问题,agent 按以下顺序调取,**不跳级**:

1. **本机记忆(Hermes 长期记忆)** —— 最快,跨会话索引。先查这里有没有已知事实。
2. **Obsidian 知识库(主库)** —— 完整沉淀(个人成长/学习/项目/方案)。记忆里只是指针,详情在此。东哥提问时须能调出。
3. **agent 自身推理** —— 已加载的对话上下文 + 模型推理。
4. **网络寻找答案论证** —— 仅当 1~3 不足时,用 web_search / 抓取做验证与补充(注意:内地网络走 Clash 代理;Google/Anthropic 等需账号的暂不可直连)。
5. **实施** —— 派活 / 写库 / 执行命令。

## 二、质量要求

- **回答严谨**:事实有出处(记忆/库/网络),不臆造。
- **推理符合逻辑**:分步推导,不跳步;涉及失败经验须点出"历史上怎么栽的"。
- Obsidian 中写的个人成长/学习/方案等内容,**本质是给 AI agent 看的索引与上下文**,东哥提问时各 agent 应能据此调出并衔接。

## 三、当前东哥的使用特征(供 agent 理解)

- 用代码时间不多,主要用于**工作推理**(钻井/定向工程 + 个人成长 + 找商机)。
- 不要求 agent 替他写大量代码,而是**辅助推理、积累、决策**。
